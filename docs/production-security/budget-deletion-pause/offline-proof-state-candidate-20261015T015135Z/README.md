# NON-RUNNABLE — FIXTURE-ONLY — NOT AUTHORIZED

This package is an offline Windows filesystem prototype for two proof-file
operations: one same-directory no-overwrite archive rename and one create-new
synthetic proof write. It is not a production adapter, contains no production
root, has no arbitrary-root input, is not bound to the selected native runner,
and cannot call Supabase, PostgreSQL, or any network service.

The only root is generated internally beneath the current process's Windows
temporary directory. Case directories and files are generated by the fixture
library. The PowerShell entrypoint accepts no arguments and uses the local
PowerShell/.NET runtime only.

## Scope and safety

- Archive performs exactly one SetFileInformationByHandle call with
  FileRenameInfo (class 3), ReplaceIfExists=FALSE, a null RootDirectory,
  and a same-directory absolute destination. It has no copy/delete fallback,
  overwrite, retry, restore, rollback, or cleanup path.
- Proof creation accepts exactly five sanitized string fields, validates an
  explicit-offset timestamp, emits UTF-8 without a BOM, and opens the target
  once with FileMode.CreateNew. It never removes a partial or complete file.
- Failure-injection points exist only for fixture tests. They model stop
  points without any production I/O.
- Test cleanup is limited to verified child directories under the generated
  per-run temporary root. Ambiguous-operation and reparse fixtures are kept;
  any run with a failing assertion retains its fixture state.

## Evidence limits

The tests can establish finite behavior on the current Windows machine and
temporary filesystem only. They do not establish production-root binding, protected-root
ACLs, security against privileged actors, Windows ACL ownership in production,
process-incarnation ownership, power-loss or directory-entry durability,
upstream request count/retry behavior, F1 authorization-wide at-most-once
consumption, F3 child-process/deadline/output boundaries, or full F2 readiness.
The earlier F2-A 28/28 result remains fixture evidence; its reparse/junction and
hardlink cases were blocked and this package does not upgrade those claims.

No production operation, evidence refresh, preflight, SQL, migration,
authorization, or installation is included or authorized.
